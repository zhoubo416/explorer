> 用途：给下一步「人工验收」用的完整手册。涵盖已开发功能、未完成项、待优化项，以及逐模块的验证方法。

## 1. 项目概况

| 项 | 内容 |
|---|---|
| 产品定位 | 基于长期记忆的 AI 个人成长 Agent |
| Web 端 | Nuxt 3 + Vue 3（`app/`），仅桌面端 |
| 移动端 | Flutter（`mobile/`），iOS + Android |
| 后端 | Supabase（PostgreSQL + pgvector + Edge Functions） |
| AI | DeepSeek（对话/推理）+ 阿里云百炼（embedding 1536 维） |
| 项目 ref | `bjbfxxvgtiatstdytzzn` |
| Supabase 地址 | `https://bjbfxxvgtiatstdytzzn.supabase.co` |

核心架构约定（见 `AGENTS.md`）：

- 对话副作用统一在后端 `explore-conversation` 完成（助手回复、记忆、成长事件、向量化、记忆关联、目标阶段/状态更新），客户端只存用户消息 + 刷新本地状态。
- 成长路径是 AI 推理结果，落库到 `explore_user_profiles.growth_dimensions / growth_composition`，UI 只读画像、不做关键词算分。

## 2. 已开发功能清单

### 2.1 账号与双端

- 注册 / 登录 / 退出，按 `auth.uid()` 隔离数据。
- Web（`app/`）与 Flutter（`mobile/`）功能已对齐：首页、目标、记忆、对话、周报、我的。
- 数据库全部 `explore_` 前缀 + RLS（每行只能本人访问）。

### 2.2 AI 对话

- 三种模式：`normal`（日常）、`low_mood`（成长陪伴）、`goal_creation`（目标共创）。
- 四层记忆召回注入：主目标阶段 + 语义相似记忆 + 用户画像 + 近期记忆。
- 返回结构化 JSON：`reply` / `memory` / `goal_update` / `goal_status_update`。

### 2.3 记忆系统（Memory OS）

- 7 类记忆：event / decision / reflection / achievement / failure / emotion / thought。
- 重要性评分（0-100）、情绪标签。
- 写入时自动向量化（百炼 1536 维），支持语义检索（`explore_match_memories` RPC）。
- 记忆关系图谱：记忆↔记忆（`similar`）+ 记忆↔目标（`related_to`）。

### 2.4 目标系统（Goal OS）

- 多目标 + 唯一主目标。
- 聊天共创目标（`explore-goal-chat`）→ 自动拆阶段 + 行动项（`explore-goal-plan`）。
- 阶段/行动项：勾选、对话自动推进（`goal_update`）、完成目标。
- 完整状态机：探索中 → 进行中 → 受阻/暂停 → 完成 → 归档（手动 + 对话两条路径）。

### 2.5 用户画像与成长路径

- `explore-profile` 提炼 personality / values / interests / strengths / weaknesses / current_stage / ai_summary。
- 同时输出 `growth_dimensions`（能力维度：score + evidence）与 `growth_composition`（成长构成：ratio + insight）。
- 首次创建目标自动建立画像（onboarding）。

### 2.6 首页与洞察

- AI 今日观察（`explore-observations`）。
- 当前主目标 + 进度。
- 今日建议（`explore-daily-suggestion`，按天缓存）。
- 最近成长记录。

### 2.7 周报、时间线与目标分析

- 成长周报（`explore-weekly-report`）+ 历史切换（`explore_weekly_reports`）。
- 成长时间线阶段总结（`explore-timeline-summary`）。
- 按目标的分析（`explore-goal-analysis` → `ai_summary`）。

### 2.8 主动成长机制

- `explore-proactive` 六类触发：情绪陪伴 → 目标停滞 → 节奏提醒 → 下一步提醒 → 成长突破 → 深度反思。
- 支持登录时按用户触发 + 定时全量模式（`CRON_SECRET` + service role）。

### 2.9 放弃目标完整流程

- 低情绪三层提问（情绪理解 → 原因探索 → 区分方向/方法），后端用 `mood_stage` 确定性推进，完成后给判断，确认后落状态。

## 6. 验证指南（逐模块）

> 验证两条腿：**UI 操作** + **SQL 查库**。下面每条都给出「做什么 + 看什么」。

### 6.0 前置检查

1. `cd /Users/bozhou/code/github/explore && npm run dev`（Web，默认 3000 端口）。
2. Flutter 用上面的 `--dart-define` 启动（mock 已移除；不配置则显示空状态，无法使用真实功能）。
3. 确认 Secret 与 SQL 都已到位（见 5.2 / 5.3）。

### 6.1 注册 / 登录

- Web：打开首页 → 注册一个测试账号 → 登录。
- 查库：`select id, email from auth.users order by created_at desc limit 5;`
- 预期：能登录进主界面，且不同账号数据互相隔离。

### 6.2 AI 对话 + 记忆自动落库

1. 进「对话」，发一句带决定/情绪的话，例如「我决定从这周开始每天做用户访谈」。
2. 再发一句纯闲聊，例如「今天天气不错」。

查库验证：

```sql
select type, content, importance, emotion, embedding is not null as has_embedding
from explore_memory_items
order by created_at desc limit 5;
```

- 预期：第一句产生一条 `decision`（importance 高），第二句不产生记忆。
- `has_embedding` 应为 `true`（向量化成功）。

### 6.3 记忆关系图谱

```sql
select source_id, target_id, target_goal_id, relation_type
from explore_memory_relations
order by id desc limit 10;
```

- 预期：`target_id` 非空为「记忆↔记忆 similar」；`target_goal_id` 非空为「记忆↔目标 related_to」。

### 6.4 用户画像 + 成长维度/构成

1. 「我的」页 → 点「生成画像 / 重新生成」。
2. 进目标详情 → 概览 Tab，看「成长构成」和「能力维度」两条进度条。

查库：

```sql
select personality, interests, strengths, weaknesses,
       current_stage, ai_summary,
       growth_dimensions, growth_composition
from explore_user_profiles;
```

- 预期：各字段非空，`growth_dimensions` 有 `score + evidence`，`growth_composition` 有 `ratio + insight`。

### 6.5 目标共创 + 阶段/行动项

1. 「成长」→「创建目标」→ 和 AI 聊，直到它提炼出目标。
2. 确认后应自动拆出 2-4 个阶段、每个阶段 2-4 个行动项。
3. 目标详情「阶段」Tab 勾选行动项，「行动」Tab 生成行动建议。

查库：

```sql
select title, status, progress, is_main_goal, jsonb_array_length(stages) as stage_count
from explore_growth_goals order by created_at desc limit 5;
```

- 预期：`stage_count >= 2`，状态从 `exploring` 起，可到 `active`。

### 6.6 对话推进目标（goal_update）

1. 在对话里说「我已经完成了第一个阶段」之类的话。
2. 回目标详情看阶段是否推进、进度是否变化。

- 预期：当前阶段标记完成、下一阶段变为 active、进度百分比上升。

### 6.7 目标状态机（手动）

在目标详情操作：开始 / 暂停 / 恢复进行 / 标记完成 / 归档，逐个点。

```sql
select title, status, progress from explore_growth_goals order by updated_at desc limit 5;
```

- 预期：`status` 在 `active/paused/blocked/completed/archived` 间正确切换；完成时 progress=100。

### 6.8 放弃目标完整流程（低情绪三层）

1. 对话页点「我有点累，想放弃」。
2. 连续回答三轮：第一层问发生了什么 → 第二层问还有没有成果/反馈 → 第三层问放弃方向还是方法。
3. 第三轮后应给判断，而不是继续追问。
4. 说「先暂停吧」，目标状态应变为 `paused`。

查库：

```sql
select mode, mood_stage from explore_conversation_sessions order by updated_at desc limit 5;
```

- 预期：`mood_stage` 从 0 递增到 3，不跳层、不重复。

### 6.9 首页（观察 + 今日建议 + 最近成长）

1. 登录进首页。
2. 看「AI 今日观察」卡片、「今日建议」一句话、「最近成长记录」。

查库：

```sql
select content, suggestion_date from explore_daily_suggestions order by created_at desc limit 5;
select content from explore_ai_observations order by created_at desc limit 5;
```

- 预期：今日建议是 AI 生成的短句（不是成功标准原文）；观察有具体内容。

### 6.10 周报 + 时间线总结

1. 「周报」页 → 生成/重新生成 → 切历史。
2. 「记忆」页 → 生成时间线阶段总结。

查库：

```sql
select week_start, score, insight from explore_weekly_reports order by week_start desc limit 5;
```

- 预期：有 score/insight，重复生成不产生重复行。

### 6.11 主动消息（目标停滞 / 情绪 / 突破 / 反思等）

1. 登录后顶部横幅 / 铃铛看主动消息；标记已读。
2. 造数据验证触发：把一个 active 目标 `updated_at` 改成 30 天前 → 应触发「目标停滞」。

查库：

```sql
select type, content, trigger_reason, status from explore_ai_actions order by created_at desc limit 10;
```

- 预期：类型包含 `encouragement / warning / insight / reminder / reflection`。

### 6.12 定时全量（已验证 2026-08-24）

```sql
select * from cron.job;
```

- 线上确认：`explore-proactive-daily` 存在且 `active=true`，调度 `0 1 * * *`（每日 UTC 01:00 = 北京 09:00）；`pg_cron`、`pg_net` 均已启用。
- 实测：2026-08-24 01:00 UTC 批量触发成功，生成 encouragement / insight / reflection / reminder 共 4 类主动消息（warning 需 30 天未更新目标才触发，无属正常）。
- 若任务缺失：检查 pg_cron / pg_net 是否开启，或重新执行 `supabase/cron.sql`（apikey 已填真实 anon key）。
